Script body:
```js
const chat = useChatbotStore();
const auth = useAuthStore();
const scrollArea = ref(null);

watch(() => chat.messages.length, async () => {
    await nextTick();
    if (scrollArea.value) {
        scrollArea.value.scrollTop = scrollArea.value.scrollHeight;
    }
});
```

## Trust Boundaries

|----------|-------------|
| authenticated SPA shell → widget | The widget renders financial data inside every authenticated page |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-22 | Information Disclosure | widget rendering on unauthenticated pages | mitigate | Mounted only in `AppLayout.vue` (never used by `views/auth/*`) plus a `v-if="auth.isAuthenticated"` guard on the trigger; checkpoint step 1 verifies the login page has no widget |
| T-17-23 | Information Disclosure | financial answers left on screen after logout | mitigate | Store state is in-memory only; a logout navigates to an `AuthLayout` view where the widget is not mounted, and a refresh clears `messages` entirely (D-05) |
| T-17-24 | Tampering | duplicate mounts causing divergent state | mitigate | Single-mount grep gate in Task 2 acceptance criteria (`ChatWidget` referenced by exactly one non-self file) |
| T-17-25 | Denial of Service | rapid chip clicking flooding the endpoint | mitigate | Chips and the Send button are `:disabled="chat.loading"` during a request; the server-side `throttle:api-read` bucket (100/min) is the hard limit |
</threat_model>
