Create `resources/js/stores/chatbot.js` as a Composition-API Pinia store named `'chatbot'`.

**Exported constants** (also used by plan 17-06's widget):

```js
export const INTENT_CHIPS = [
    { id: 'balances', label: 'Check account balances', intent: 'account_balances', params: {} },
    { id: 'upcoming', label: 'See upcoming payments', nextStep: 'upcoming_days' },
    { id: 'spending', label: "View this month's spending", nextStep: 'spending_period' },
];

export const UPCOMING_DAYS_CHIPS = [
    { id: 'days-3', label: 'Next 3 days', intent: 'upcoming_payments', params: { days: 3 } },
    { id: 'days-7', label: 'Next 7 days', intent: 'upcoming_payments', params: { days: 7 } },
    { id: 'days-30', label: 'Next 30 days', intent: 'upcoming_payments', params: { days: 30 } },
];

export const SPENDING_PERIOD_CHIPS = [
    { id: 'this-month', label: 'This month', intent: 'monthly_spending', params: {} },
    { id: 'last-month', label: 'Last month', intent: 'monthly_spending', paramsFactory: 'previous_month' },
];

const MONTH_PATTERN = /^\d{4}-(0[1-9]|1[0-2])$/;
```

**State (all plain in-memory refs — never `localStorage`, D-05):**
`isOpen` (false), `messages` ([]), `quickReplies` (INTENT_CHIPS), `activeStep` ('intent_select'), `freeTextEnabled` (false), `freeTextPlaceholder` (''), `loading` (false).

**Message objects** pushed onto `messages`:
```js
{ id: <incrementing number>, role: 'user' | 'bot', kind: 'text' | 'answer' | 'error' | 'out_of_scope',
  text: string, subtext: string | null, answer: object | null }
```

**Actions:**

- `open()` / `close()` / `toggle()` — set `isOpen`.
- `reset()` — `messages = []`, `quickReplies = INTENT_CHIPS`, `activeStep = 'intent_select'`, `freeTextEnabled = false`, `freeTextPlaceholder = ''`.
- `selectQuickReply(chip)`:
  1. Push a user message `{ role: 'user', kind: 'text', text: chip.label }`.
  2. If `chip.nextStep === 'upcoming_days'`: set `quickReplies = UPCOMING_DAYS_CHIPS`, `activeStep = 'upcoming_days'`, `freeTextEnabled = false`, push a bot `text` message `'How far ahead should I look?'` and return.
  3. If `chip.nextStep === 'spending_period'`: set `quickReplies = SPENDING_PERIOD_CHIPS`, `activeStep = 'spending_period'`, `freeTextEnabled = true`, `freeTextPlaceholder = 'Or type a month, e.g. 2026-03'`, push a bot `text` message `'Which month should I summarise?'` and return.
  4. Otherwise resolve params: if `chip.paramsFactory === 'previous_month'`, compute `{ month: <previous month as YYYY-MM> }` from `new Date()` (pad the month to two digits; handle the January→December year rollover); else use `chip.params ?? {}`. Then `await ask(chip.intent, params)`.
- `submitFreeText(value)`:
  1. Trim the value; ignore empty input.
  2. Push a user message with the raw trimmed text.
  3. If `MONTH_PATTERN.test(trimmed)` → `await ask('monthly_spending', { month: trimmed })`.
  4. Else push a bot `out_of_scope` message with `text = 'I can only help with balances, upcoming payments, and monthly spending right now.'` and `subtext = 'Try one of the options below.'`, then call the internal `backToIntentSelect()` helper.
     Do NOT scan the input for domain keywords (credit card / loan / subscription / budget) and do NOT send unrecognised text to the backend — anything that is not a valid month is out of scope by definition (D-01, RESEARCH.md Pitfall 4).
- `ask(intent, params)`:
  ```js
  const auth = useAuthStore();
  loading.value = true;
  try {
      const response = await fetch('/api/v1/chatbot/ask', {
          method: 'POST',
          headers: {
              Authorization: `Bearer ${auth.accessToken}`,
              'Content-Type': 'application/json',
              Accept: 'application/json',
          },
          body: JSON.stringify({ intent, params }),
      });
      const data = await response.json();
      if (!response.ok) {
          pushError(data);
          return;
      }
      pushMessage({ role: 'bot', kind: 'answer', text: data.data.headline, subtext: data.data.empty_message, answer: data.data });
  } catch {
      pushMessage({ role: 'bot', kind: 'error', text: "Couldn't get an answer right now.", subtext: 'Check your connection and try again.' });
  } finally {
      loading.value = false;
      backToIntentSelect();
  }
  ```
  `pushError(data)`: if `data?.errors?.intent?.[0]` exists, push an `out_of_scope` message using that server message as `text` and `'Try one of the options below.'` as `subtext`; otherwise push the `error` kind message with the two locked error strings.

- `backToIntentSelect()` (internal, not exported): `quickReplies = INTENT_CHIPS`, `activeStep = 'intent_select'`, `freeTextEnabled = false`, `freeTextPlaceholder = ''`. Called after every answered turn because the backend is stateless (D-04) — a follow-up question always starts from the intent chips again.

Import `useAuthStore` from `@/stores/auth.js`.

Return every ref and action from the setup function so components can destructure via `storeToRefs`.

Forbidden in this file: any `localStorage`/`sessionStorage` call, any persistence plugin, any intent key other than the three listed, any keyword-matching of free text against finance domains.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user keyboard → free-text input | Arbitrary text enters the client |
| client store → `/api/v1/chatbot/ask` | Client-supplied intent/params cross into the API |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-18 | Information Disclosure | free-text step used to probe out-of-scope domains | mitigate | Store only sends free text when it matches `/^\d{4}-(0[1-9]\|1[0-2])$/`; anything else renders the locked out-of-scope copy client-side and is never transmitted |
| T-17-19 | Information Disclosure | chat history persisting on a shared device | mitigate | No `localStorage`/`sessionStorage` and no persistence plugin (D-05); grep gate in acceptance criteria enforces it |
| T-17-20 | Spoofing | request sent without credentials | mitigate | Every `ask()` attaches `Authorization: Bearer ${auth.accessToken}` from the existing auth store; the API rejects anonymous calls with 401 regardless |
| T-17-21 | Tampering | client-side validation treated as the security boundary | accept | Client checks are UX only; `AskChatbotRequest` + `IntentRouter` re-validate every field server-side (plan 17-04). No client-only trust is assumed |
</threat_model>
