## Spacing Scale

Declared values (must be multiples of 4), matching the scale already in use across `AppNavbar.vue`, `KpiCard.vue`, `ConfirmModal.vue`, `DataTable.vue`:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps inside quick-reply chips |
| sm | 8px | Gap between chat bubbles in a turn, chip internal row gaps |
| md | 16px | Message bubble padding, panel content padding |
| lg | 24px | Panel header padding, floating-trigger offset from viewport edge |
| xl | 32px | Space between distinct conversation "turns" (bot answer + its quick replies) |
| 2xl | 48px | Not used in this phase's widget (reserved for future full-page chat view) |
| 3xl | 64px | Not used in this phase's widget |

Exceptions:
- Floating trigger button: 56×56px (`h-14 w-14`) circular button — multiple of 4, sized above the 44px minimum touch target for a primary global action.
- Quick-reply chips: 44px min height (`h-11`) — touch-target exception over the codebase's default `h-10` (40px) buttons, because chips are the primary input mode (D-02) and need a larger mobile tap target.
- Chat panel width: 380px desktop (fixed), full viewport width on mobile (`<640px`) — not on the 4px spacing scale by definition (it's a layout dimension, not a spacing token), noted here to avoid ambiguity.

## Typography

Reuses the project's existing size vocabulary (`text-xs`/`text-sm`/`text-base` dominate the codebase per grep of `resources/js/components` and `resources/js/views`). Two weights only, per contract discipline — new chatbot components use `font-normal` (400) and `font-semibold` (600) exclusively; do not introduce `font-medium` (500) in new Phase 17 components even though it exists elsewhere in the codebase (legacy nav/button styling).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 (`font-normal`) | 1.5 — message text, input placeholder, timestamps |
| Label | 12px (`text-xs`) | 600 (`font-semibold`) | 1.4 — quick-reply chip labels, panel section headers ("Choose a question") |
| Heading | 16px (`text-base`) | 600 (`font-semibold`) | 1.2 — widget panel title ("Ask Fluxa"), bot turn intro line |
| Display | 20px (`text-xl`) | 600 (`font-semibold`) | 1.2 — prominent numeric answer highlight (e.g. the returned account balance figure), mirrors `KpiCard.vue`'s value treatment |

## Color

Follows the 60/30/10 split already established across `AppNavbar.vue`, `EmptyState.vue`, `ConfirmModal.vue`, and `DataTable.vue` — white/gray dominant and secondary surfaces, amber accent, red destructive/error.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` (`bg-white`) | Chat panel background, message scroll area background |
| Secondary (30%) | `#F9FAFB` / `#F3F4F6` (`bg-gray-50` / `bg-gray-100`), border `#E5E7EB` (`border-gray-200`) | Bot message bubbles, panel header bar, quick-reply chip default (unselected) state, panel border |
| Accent (10%) | `#F59E0B` / hover `#D97706` (`bg-amber-500` / `hover:bg-amber-600`) | Floating trigger button, user message bubble background, focus ring on chips/inputs (`focus:ring-amber-300`), the free-text "Send" button |
| Destructive/Error | `#DC2626` (`text-red-600`), banner `bg-red-50` / `border-red-200` | Inline error banner when an intent's data fetch fails — no destructive *actions* exist in this phase (read-only per D-01), only an error *state* needs this color |

Accent reserved for: the floating trigger button, the user's own message bubbles (to visually separate user vs. bot turns), focus rings on interactive controls, and the free-text step's submit button. Accent is never used for bot message bubbles, panel chrome, or body text — those stay on dominant/secondary surfaces per the 60/30/10 discipline.

## Copywriting Contract

Tone matches existing error/empty-state copy in `DataTable.vue` ("Couldn't load data" / "Check your connection and try again.") and `EmptyState.vue`. Intent scope is fixed to D-07 (account balances, upcoming payments, monthly spending/cashflow) — copy must never imply broader capability.

| Element | Copy |
|---------|------|
| Floating trigger button (aria-label / tooltip) | "Ask Fluxa" |
| Panel header title | "Ask Fluxa about your finances" |
| Empty state heading (first open, no messages yet) | "What would you like to check?" |
| Empty state body | "Pick a question below to get started." |
| Quick-reply chip — Intent 1 | "Check account balances" |
| Quick-reply chip — Intent 2 | "See upcoming payments" |
| Quick-reply chip — Intent 3 | "View this month's spending" |
| Error state (fetch/network failure answering an intent) | "Couldn't get an answer right now." — "Check your connection and try again." |
| Out-of-scope input (free text names a structural-only domain, e.g. credit cards/loans/subscriptions/budgets) | "I can only help with balances, upcoming payments, and monthly spending right now." — "Try one of the options below." |
| Destructive confirmation | Not applicable — Phase 17 is read-only per D-01; no write/destructive actions are introduced, so no confirmation modal is needed for this phase's scope |
