<objective>
Add a manual Artisan command that lists every active credit card (all users) with its current balance, opening balance, and expense/paid-principal breakdown, flagging cards created before the balance-recompute bug's introduction (2026-08-06 — see plan 21-01's fix and RESEARCH.md section 1) so the card owner can manually cross-check them against real statements and correct `opening_balance` via Filament where needed.

Purpose: D-09/D-10 (21-CONTEXT.md) deliberately chose NOT to auto-reconstruct historical balances — the true pre-bug value isn't derivable from current data. This command is the promised "tell me which cards to check" step, so the user isn't left reviewing every card blind after 21-01's migration ships.

Depends on plan 21-01: needs the `opening_balance` column and corrected `syncCardBalance()` invariant to exist first (the command reads `opening_balance` directly).

RESEARCH.md section 2 finding this plan must honor: the nightly `credit-cards:generate-cycles` job (`routes/console.php`, scheduled `dailyAt('02:00')`) already calls `syncCardBalance()` unconditionally for every ACTIVE card, regardless of payment history. So "cards with a payment created/updated after the bug date" (21-CONTEXT.md's original, narrower framing of D-10) is NOT the right filter — use card `created_at` relative to the bug date instead, since that's what actually determines whether a card has been silently recomputed by the nightly job.

Output: one closure-style Artisan command in `routes/console.php` (matching the existing `credit-cards:generate-cycles` / `loans:sync-installments` convention — no `app/Console/Commands/*.php` class exists in this app, don't introduce one), not scheduled, plus a Feature test.

**Post-review correction, round 1 (code review, 2026-09-17):** everywhere below this note references `2026-08-06` (the bug's introduction date) as the CHECK-flag threshold — that was wrong. Round 1 switched the gate to `fixDeployedAt` (`2026-09-17 12:00:00`, the migration's own timestamp) instead, since a card created after the bug but before this fix (e.g. 2026-09-01) was exposed to the nightly recompute for its whole lifetime too.

**Post-review correction, round 2 (code review, 2026-09-17):** round 1's `fixDeployedAt` was itself unsound — a migration filename's timestamp isn't proof of when the migration actually ran in a given environment; a later real deploy would leave a gap of unflagged-but-exposed cards again. **The as-shipped command drops date-based flagging entirely**: it lists every active card (oldest `created_at` first, as a review-prioritization aid only) with no CHECK column, and its message instructs the user to cross-check all of them — the only criterion that cannot silently miss a genuinely at-risk card, since no in-data signal can reliably distinguish safe from at-risk here. See `21-RESEARCH.md`'s matching correction note (round 2) and `21-02-SUMMARY.md` for the executed fix.

Add to `routes/console.php`, after the existing `credit-cards:generate-cycles` command definition and before `loans:sync-installments` (keep related credit-card commands grouped together):

```php
Artisan::command('credit-cards:balance-audit', function () {
    $bugIntroducedAt = Carbon::parse('2026-08-06 03:02:12');

    $cards = CreditCard::query()
        ->withoutUserScope()
        ->where('status', CreditCardStatus::ACTIVE)
        ->with('user:id,email')
        ->get();

    $rows = $cards->map(function (CreditCard $card) {
        $expenses = (float) $card->expenses()->sum('amount');
        $paidPrincipal = (float) $card->payments()
            ->where('status', \App\Enums\CreditCardPaymentStatus::PAID)
            ->sum('principal_amount');

        return [
            $card->id,
            $card->user?->email ?? '—',
            $card->name,
            $card->type?->value ?? '—',
            number_format((float) $card->current_balance, 2),
            number_format((float) $card->opening_balance, 2),
            number_format($expenses, 2),
            number_format($paidPrincipal, 2),
            $card->created_at->lt($bugIntroducedAt) ? 'CHECK' : '',
        ];
    });

    $this->table(
        ['ID', 'User', 'Name', 'Type', 'Current balance', 'Opening balance', 'Expenses', 'Paid principal', 'Pre-fix?'],
        $rows
    );

    $checkCount = $rows->filter(fn ($row) => $row[8] === 'CHECK')->count();

    $this->info("{$cards->count()} active card(s) listed, {$checkCount} flagged CHECK.");
    $this->line("'Pre-fix?' = CHECK means the card existed before the balance-recompute fix ({$bugIntroducedAt->toDateString()}) and its 'Current balance' may have been silently recomputed by the nightly credit-cards:generate-cycles job before Opening balance existed. Cross-check these against real statements and correct 'Opening balance' in Filament where needed.");
})->purpose('List active credit cards with a balance breakdown for manual reconciliation after the opening_balance fix (Phase 21) — not scheduled, run manually');
```

namespace Tests\Feature;

            'account_id' => $account->id,
            'name' => 'Post-fix audit card',
            'type' => CreditCardType::REVOLVING,
            'credit_limit' => 1000,
            'statement_day' => 28,
            'due_day' => 15,
            'skip_weekends' => true,
            'current_balance' => 0,

            'type' => CreditCardType::REVOLVING,
            'credit_limit' => 1000,
            'statement_day' => 28,
            'due_day' => 15,
            'skip_weekends' => true,
            'current_balance' => 0,
            'status' => CreditCardStatus::CLOSED,
            'stamp_duty_amount' => 2,
        ]);

            ->assertSuccessful();

        $this->assertStringContainsString('Post-fix audit card', $output);
        $this->assertStringNotContainsString('Closed audit card', $output);

        $this->assertSame(400.0, (float) $preFixCard->current_balance);
