# Plan 25-01 — staging model and safe file intake

## Objective

Accept a CSV/XLSX upload for an owned account or card, hold it safely, and expose a preview, without creating any ledger record.

## Read first

`25-CONTEXT.md`, `25-RESEARCH.md`, `Transaction`, `CreditCardExpense`, `OwnedByAuthenticatedUser`, an existing API controller + request + feature test (e.g. `SavingGoalController`), `config/filesystems.php`, the scheduler registration and `ScheduledCommandErrorIsolationTest`.

## Work

1. Migrations and models `ImportBatch` / `ImportRow` (see RESEARCH decision 2), owner-scoped like other models, with `statement_ending_balance` nullable (D-06) and statuses as enums.
2. `ImportFileReader`: CSV and XLSX only (content + extension), size/row/decompressed-size limits, read-data-only, no formula evaluation or external links, returns plain string cells. Unsupported/oversized/odd files fail with a clear validation error.
3. `POST /api/v1/import-batches` (target account or card, file, optional ending balance and period), `GET /api/v1/import-batches/{id}` (status + first N preview rows), `DELETE`. Ownership of target and batch enforced; throttled. The raw file is parsed in the request and not stored; staged cells are encrypted at rest.
4. Scheduled `imports:purge-abandoned` command for unconfirmed batches, with the existing per-item error isolation.
5. Tests: limits, XLSX formula/bomb handling, wrong type, other user's target/batch, purge, nothing written to `transactions`/`credit_card_expenses`.

## Acceptance

No ledger or balance change from any call in this plan; a stranger can never read or delete another user's batch; an unconfirmed batch does not outlive its retention period.

## Output

`25-01-SUMMARY.md`.
