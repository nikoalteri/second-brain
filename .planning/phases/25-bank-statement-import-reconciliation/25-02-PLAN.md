# Plan 25-02 — column mapping, normalisation and duplicate detection

## Objective

Turn raw cells into normalised draft rows via a saved, versioned mapping, and classify likely duplicates and look-alikes.

## Read first

`25-RESEARCH.md` (decisions 4-6), `25-01-SUMMARY.md`, `CreditCardPayment`, the subscription renewal posting columns.

## Work

1. `ImportMapping` (per owner + target) storing columns and explicit parsing options; `PUT /api/v1/import-batches/{id}/mapping` validates it, saves it, and normalises rows (decimal-string parsing to minor units, explicit date format, sign inversion, debit/credit columns, optional category-name match to the owner's categories).
2. Row fingerprint with occurrence index; unique per owner+target to block re-importing the same file; within-file duplicates flagged.
3. Duplicate classifier against the ledger (`exact | probable | none`, ±3 days, equal minor units, description similarity) plus transfer / card-payment / renewal look-alike flags. Proposals only.
4. Re-applying an edited mapping re-normalises draft rows and leaves discarded/confirmed rows alone.
5. Tests for every edge case in RESEARCH that concerns parsing and matching.

## Acceptance

Same file twice does not stage twice; two legitimate identical charges both survive; no match is ever auto-discarded.

## Output

`25-02-SUMMARY.md`.
