# Plan 22-03 — owner-facing REST, SPA bell, and Filament view

## Objective

Make digest notifications visible and readable in the authenticated SPA and the existing Filament resource, without exposing one user's finance data to another.

## Read first

`22-CONTEXT.md`, `22-RESEARCH.md`, the 22-01/02 summaries, `routes/api.php`, `AppNavbar.vue`, `AppLayout.vue`, SPA auth/client conventions, and the existing Filament notification resource, pages, form and table.

## Work

1. Add authenticated REST `GET /api/v1/notifications` under the read limiter and `PATCH /api/v1/notifications/{notification}/read` under the write limiter. The list is newest-first, bounded (max 100 per page), includes unread count and only safe fields (`id`, title, message, type, `read_at`, created time, internal action URL). Filter by `request->user()->id` explicitly, including for a superadmin. The mark-read action sets `read_at` once and is idempotent; a foreign ID returns 404. Do not accept user ID, content, type, or URL from the client.
2. Add a bell with unread badge and a finite, accessible notification list in `AppNavbar.vue` on desktop and mobile. Fetch when the authenticated layout loads and refresh when the panel opens; handle loading, empty and error states. Opening a notification marks it read, updates the badge, and follows only a validated internal route. Add English labels through the existing i18n file. Keep `UserSetting::KEY_NOTIFICATIONS` as the existing toast preference; the persistent notification center is shown regardless of the toast setting.
3. Adapt the **existing** Filament `NotificationResource`: make financial notifications visibly reachable, show owner/title/message/created/read state, add a mark-read action, and apply appropriate access policy/query scoping. Remove or constrain create/edit/delete actions that permit arbitrary owner reassignment or changes to generated finance alerts. Do not create a duplicate resource.

## Acceptance and verification

- API feature tests cover guest rejection, own list/count, superadmin own-only behavior, foreign ID 404, idempotent read, bounded paging and safe response fields.
- Filament feature tests cover reachability, owner isolation for ordinary admins, controlled superadmin access and mark-read behavior; preserve existing panel MFA/access rules.
- Frontend build passes. Browser-check the bell and read flow on desktop and mobile against seeded notifications; verify the `important_only` toast preference does not hide the center.
- Run relevant API/Filament tests and then the full backend suite. Record the results and any browser/deployment gaps in `22-03-SUMMARY.md`.

## Output

Create `22-03-SUMMARY.md`, then update ROADMAP/STATE only after implementation and verification have actually completed.
