<objective>
Close the two remaining confirmed findings in the credit-card observer/service chain: the fail-open validation in `CreditCardExpenseService::validateExpenseChange()`, and the untested static-state reentrancy in `CreditCardExpenseObserver` / `CreditCardPaymentObserver`.

Purpose:
1. `app/Services/CreditCardExpenseService.php:32-34` does `$currentCard = CreditCard::query()->lockForUpdate()->find((int) $expense->credit_card_id); if (! $currentCard) { return; }` — a missing target card causes validation to silently **pass** instead of rejecting the mutation. Orphaned/invalid `credit_card_id` values are a data-integrity risk, which D-02 classifies as high severity → fix in this phase with a regression test.
2. `CreditCardExpenseObserver.php:15` (`private static array $originalPointers`) and `CreditCardPaymentObserver.php:16` (`private static array $previousStatuses`) carry state between the `updating` and `updated` events. No Octane/Swoole is in use (verified: `composer.json` has no `laravel/octane`), so this does NOT leak across HTTP requests. The real, untested risk is **intra-request**: if a write fails between `updating` and `updated`, the entry is never `unset()`, and a later update of the same record id in the same process reads stale pointers. This plan attempts a concrete reproduction and applies D-02's severity policy to the result.

Runs in wave 2 because it shares the credit-card payment sync semantics that plan 18-04 changes; sequencing avoids two plans reasoning about the same observer → service chain simultaneously.

Output: A fail-closed validation path with regression tests, and an observer reentrancy test suite plus either a fix or a documented lower-severity finding.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → `POST/PUT /credit-cards/{card}/expenses/{expense}` | Client-supplied `credit_card_id` crosses into service validation and must be proven to exist before any balance math runs |
| Model event `updating` → `updated` | Process-global static arrays carry state across this boundary; a failed write between them is an unhandled path |
| Service → `credit_cards.current_balance` / `credit_card_cycles.status` | Money state derived from the values carried across the boundary above |
