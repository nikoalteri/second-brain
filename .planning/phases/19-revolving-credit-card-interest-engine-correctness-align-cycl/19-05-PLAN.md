The flow this plan drives (app/Services/CreditCardCycleService.php):
```php
public function ensureCurrentMonthCycle(CreditCard $card, ?Carbon $referenceDate = null): CreditCardCycle
public function issueCycle(CreditCardCycle $cycle): bool   // computes the breakdown, updates the cycle, creates a PENDING CreditCardPayment
public function syncCardBalance(CreditCard $card): void    // current_balance = sum(expenses.amount) - sum(PAID payments.principal_amount)
```

Existing feature-test conventions (tests/Feature/CreditCardLifecycleIntegrationTest.php):
```php

$payment->update(['status' => CreditCardPaymentStatus::PAID, 'actual_date' => Carbon::parse('...')]);
```

Marking a payment PAID fires `CreditCardPaymentObserver::updated()`, which posts a transaction against
the settlement account (reducing `Account.balance` by the payment's `total_amount`) and recomputes
`CreditCard.current_balance` via `syncCardBalance()`.
