# Plan 24-03 — dashboard forecast and verification

## Objective

Show the 30-day known-commitments estimate on the existing SPA Dashboard with its breakdown and data-coverage limits.

## Read first

`24-CONTEXT.md`, `24-RESEARCH.md`, `24-02-SUMMARY.md`, `DashboardView.vue`, `useCurrency.js`, auth store and current dashboard frontend tests.

## Work

1. Fetch the new forecast endpoint independently of the existing three-day upcoming list and charts. Render each currency's available balance, counted commitments and estimated remainder, with due-date/type breakdown and visible reasons for items not deducted. Format every amount with its own currency code using `formatCurrency(amount, currency)`.
2. Label the card as an estimate of known commitments over 30 days. Show `as_of`/`through_date`, an incomplete-data state for overdue/unresolved/card-settlement gaps, and copy explaining that future untracked spending/income and unreconciled bank data are not included. For empty or unknown-currency-only data, show an honest unavailable/empty state rather than a fabricated zero-safe-to-spend claim.
3. Keep dashboard loading/errors isolated so a forecast failure does not erase existing charts and reminders. Clear forecast state on logout/account switch or suppress late responses from a previous auth session; follow the notification-store session-guard pattern where useful.
4. Add a meaningful frontend test for currency-separated rendering, incomplete coverage and stale-session response behavior. Run the SPA build and relevant frontend test. Review the rendered Dashboard at desktop and mobile sizes in a local browser when an authenticated test environment is available; record any unverified visual check rather than claiming it passed.

## Acceptance and verification

- The displayed figure matches the API per currency and never silently mixes EUR/USD or double subtracts posted/card-financed charges.
- A partial estimate is visibly partial; the 3-day reminder panel keeps its existing semantics.
- Run targeted frontend tests, SPA build and appropriate backend smoke tests. Record browser-check status separately.

## Output

Create `24-03-SUMMARY.md` with UI states, validation and any environment-dependent visual follow-up.
